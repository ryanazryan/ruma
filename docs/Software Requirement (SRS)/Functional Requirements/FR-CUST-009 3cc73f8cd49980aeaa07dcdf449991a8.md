## Overview

This requirement defines the process that allows an authenticated customer to save a product to their wishlist.

The saved product can subsequently be viewed from the customer's Wishlist.

## Description

The system shall allow an authenticated customer to add an available product to their wishlist.

The system shall verify that the selected product exists before creating the wishlist item.

The system shall associate the wishlist item with the authenticated customer's account.

The system shall prevent duplicate wishlist entries for the same customer and product.

## Actors

| Actor Role | Description |
| --- | --- |
| **Customer** | Selects a product and adds it to their wishlist. |
| **System** | Authenticates the customer, verifies the product, creates the wishlist item, and returns the result. |

## Preconditions

- The customer has an existing account.
- The customer is authenticated.
- The authentication session is valid.
- The associated customer account exists.
- The selected product exists.
- The system can access the database.

## Trigger

The customer selects **Add to Wishlist** for a product.

## Main Flow

1. The customer views a product.
2. The customer selects **Add to Wishlist**.
3. The system verifies the customer's authentication session.
4. The system verifies that the selected product exists.
5. The system checks whether the product is already present in the customer's wishlist.
6. If the product is not already present, the system creates a wishlist item.
7. The system associates the wishlist item with the authenticated customer.
8. The system persists the wishlist item.
9. The system returns a successful response.
10. The product is displayed as saved in the customer's wishlist state.

## Alternative Flow

### A1 — Authentication Required

- The customer does not have a valid authentication session.
- The system rejects the request.
- No wishlist item is created.

### A2 — Product Not Found

- The selected product does not exist.
- The system rejects the request.
- No wishlist item is created.

### A3 — Product Already in Wishlist

- The selected product is already saved in the customer's wishlist.
- The system does not create a duplicate wishlist item.
- The system returns an appropriate response indicating that the product is already saved.

### A4 — Product Not Available

- The selected product is not available according to the configured product availability state.
- The system rejects the wishlist operation when the product is not eligible for saving.
- No wishlist item is created.

### A5 — Wishlist Creation Failure

- The system cannot persist the wishlist item.
- The system returns an appropriate error response.
- No incomplete wishlist item is treated as successfully created.

## Postconditions

### If Successful

- A wishlist item exists for the authenticated customer and selected product.
- The customer can view the product from their Wishlist.
- The same product is not duplicated within the customer's wishlist.

### If Failed

- No unintended wishlist item is created.
- Existing wishlist items remain unchanged.

## Business Rules

| Rule ID | Rule |
| --- | --- |
| **BR-CUST-041** | Only an authenticated customer can add products to a wishlist. |
| **BR-CUST-042** | A wishlist item must belong to the authenticated customer's wishlist. |
| **BR-CUST-043** | The selected product must exist before a wishlist item is created. |
| **BR-CUST-044** | The same product must not appear more than once in the same customer's wishlist. |
| **BR-CUST-045** | Products must satisfy the configured eligibility rules before being added to a wishlist. |
| **BR-CUST-046** | A failed wishlist operation must not modify unrelated wishlist items. |

## Validation Rules

| Field | Validation |
| --- | --- |
| **Authentication Session** | Must be valid and associated with an existing customer. |
| **Product Identity** | Must reference an existing product. |
| **Wishlist Ownership** | Must correspond to the authenticated customer. |
| **Duplicate Wishlist Entry** | The same product must not already exist in the customer's wishlist. |

## Acceptance Criteria

- An authenticated customer can add an eligible product to their wishlist.
- An unauthenticated customer cannot add a product to a wishlist.
- The selected product must exist.
- A customer cannot create a wishlist entry for another customer.
- The same product cannot be duplicated in a customer's wishlist.
- An invalid or unavailable product is rejected according to the configured eligibility policy.
- A successful wishlist addition is persisted.
- The saved product appears in the customer's Wishlist.
- A failed wishlist operation does not modify unrelated wishlist entries.

## Notes

- A wishlist item represents a relationship between a customer and a product.
- The exact wishlist persistence structure is to be defined during implementation.
- Duplicate wishlist entries should be prevented both through application logic and, where appropriate, database constraints.
- Product availability and wishlist eligibility rules must follow the final Product Catalog data model.
- Wishlist behavior should remain independent of the product's brand so that the multi-brand catalog remains compatible with the customer wishlist experience. The PRD requires the catalog to support multiple brands and suppliers without fundamental changes to the marketplace architecture.
