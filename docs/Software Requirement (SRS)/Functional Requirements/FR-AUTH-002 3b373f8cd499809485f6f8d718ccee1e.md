## Overview

Requirement ini mendefinisikan proses verifikasi alamat email pengguna setelah registrasi berhasil. Verifikasi email bertujuan memastikan bahwa alamat email yang digunakan valid dan dimiliki oleh pengguna sehingga akun dapat diaktifkan untuk menggunakan seluruh fitur Moorlife Marketplace.

## Description

Sistem harus memverifikasi alamat email pengguna menggunakan token verifikasi yang dikirim melalui email. Setelah proses verifikasi berhasil, status akun berubah dari **Unverified** menjadi **Verified**.

## Actor

| **Actor** | **Role** |
| --- | --- |
| Customer | Membuka tautan verifikasi dari email. |
| System | Memvalidasi token verifikasi dan mengaktifkan akun pengguna. |

## Main Flow

1. Pengguna membuka email verifikasi.
2. Pengguna mengklik tautan Verify Email.
3. Sistem menerima token verifikasi.
4. Sistem memvalidasi token.
5. Sistem memastikan token masih berlaku.
6. Sistem memastikan akun masih berstatus Unverified.
7. Sistem mengubah status akun menjadi Verified.
8. Sistem menghapus atau menandai token sebagai sudah digunakan.
9. Sistem menampilkan halaman **Email Verification Successful.**
10. Pengguna dapat melanjutkan ke halaman Login.

## Alternative Flow

### A1 - Token tidak valid

- Sistem menolak proses verifikasi.
- Sistem menampilkan pesan: “Token verifikasi tidak valid”

### A2 - Token telah kadaluwarsa

- Sistem menolak proses verifikasi.
- Sistem meminta pengguna mengirim ulang email verifikasi.

### A3 - Akun sudah terverifikasi

- Sistem tidak melakukan perubahan data.
- Sistem menampilkan informasi bahwa akun telah diverifikasi sebelumnya.
- Sistem mengarahkan pengguna ke halaman Login.

### A4 - Token telah digunakan

- Sistem menolak proses verifikasi.
- Sistem menampilkan pesan bahwa tautan sudah tidak berlaku.

## Postconditions

Jika berhasil:

- Status akun berubah menjadi **Verified**.
- Token verifikasi tidak dapat digunakan kembali.
- Pengguna dapat melakukan login dan menggunakan seluruh fitur sesuai hak akses.

Jika gagal:

- Status akun tetap **Unverified**.
- Token tetap berlaku jika belum kedaluwarsa (kecuali token sudah digunakan).

## **Business Rules**

| **Rule ID** | **Rule** |
| --- | --- |
| BR-AUTH-006 | Setiap akun baru wajib melakukan verifikasi email sebelum akun diaktifkan. |
| BR-AUTH-007 | Token verifikasi hanya dapat digunakan satu kali. |
| BR-AUTH-008 | Token verifikasi memiliki masa berlaku (misalnya 24 jam). |
| BR-AUTH-009 | Setelah akun terverifikasi, status akun berubah menjadi **Verified**. |
| BR-AUTH-010 | Pengguna dapat meminta pengiriman ulang email verifikasi jika token telah kedaluwarsa. |

## Validation Rules

| **Field** | **Validation** |
| --- | --- |
| Verification Token | Wajib ada dan sesuai dengan token yang tersimpan di sistem. |
| Token Expiration | Token belum melewati masa berlaku. |
| Verification Status | Akun belum pernah diverifikasi sebelumnya. |

## Acceptance Criteria

- Pengguna dapat memverifikasi email menggunakan tautan yang valid.
- Token yang tidak valid ditolak oleh sistem.
- Token yang telah kedaluwarsa tidak dapat digunakan.
- Token hanya dapat digunakan satu kali.
- Status akun berubah menjadi **Verified** setelah verifikasi berhasil.
- Pengguna dapat login menggunakan akun yang telah diverifikasi.

## Notes

- Token verifikasi harus dibuat menggunakan nilai acak yang aman secara kriptografi (cryptographically secure random value).
- Token disimpan dalam bentuk hash di database untuk meningkatkan keamanan.
- Token tidak boleh dapat ditebak (unguessable).
- Token yang sudah digunakan atau kedaluwarsa tidak boleh dapat digunakan kembali.
- Sistem harus menyediakan mekanisme **Resend Verification Email** tanpa mengharuskan pengguna membuat akun baru.
