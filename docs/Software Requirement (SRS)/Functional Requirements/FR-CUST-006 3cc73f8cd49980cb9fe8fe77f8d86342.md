## Overview

This requirement defines the process that allows an authenticated customer to update an existing saved shipping address in their Address Book.

The customer can modify their own saved address information while preserving the association between the address and their account.

## Description

The system shall allow an authenticated customer to update an existing address belonging to their account.

The system shall validate the updated address information before persisting the changes.

The system shall prevent a customer from modifying an address belonging to another customer.

## Actors

| Actor Role | Description |
| --- | --- |
| **Customer** | Selects an existing address, modifies its information, and submits the changes. |
| **System** | Authenticates the request, verifies address ownership, validates the updated information, and persists the changes. |

## Preconditions

- The customer has an existing account.
- The customer is authenticated.
- The authentication session is valid.
- The associated customer account exists.
- The address exists.
- The address belongs to the authenticated customer.
- The system can access the database.

## Trigger

The customer selects an existing saved address and submits updated information.

## Main Flow

1. The customer opens the **Address Book**.
2. The system displays the customer's saved addresses.
3. The customer selects an address to edit.
4. The system displays the current address information.
5. The customer modifies the address information.
6. The customer submits the updated address.
7. The system verifies the customer's authentication session.
8. The system verifies that the address belongs to the authenticated customer.
9. The system validates the updated address information.
10. The system updates the address record.
11. The system returns a successful response.
12. The updated address is displayed in the Address Book.

## Alternative Flow

### A1 — Authentication Required

- The customer does not have a valid authentication session.
- The system rejects the request.
- The address is not modified.

### A2 — Address Not Found

- The requested address does not exist.
- The system rejects the update request.
- No address is modified.

### A3 — Address Does Not Belong to Customer

- The requested address belongs to another customer.
- The system rejects the request.
- The address is not modified.
- The system does not expose the other customer's address information.

### A4 — Invalid Address Data

- The updated address information does not satisfy the configured validation rules.
- The system rejects the request.
- The existing address remains unchanged.

### A5 — Customer Account Not Found

- The authenticated session references a customer account that is no longer available.
- The system rejects the request.
- The address is not modified.

### A6 — Address Update Failure

- The system cannot persist the updated address information.
- The system returns an appropriate error response.
- The existing address remains unchanged.

## Postconditions

### If Successful

- The selected address is updated.
- The updated address remains associated with the authenticated customer.
- The updated address can be viewed from the Address Book.

### If Failed

- The existing address remains unchanged.
- No unrelated address data is modified.

## Business Rules

| Rule ID | Rule |
| --- | --- |
| **BR-CUST-026** | Only an authenticated customer can edit an address. |
| **BR-CUST-027** | A customer can only edit an address belonging to their own account. |
| **BR-CUST-028** | Updated address information must satisfy the configured validation rules. |
| **BR-CUST-029** | The system must verify address ownership before modifying an address. |
| **BR-CUST-030** | An unsuccessful address update must not overwrite the existing valid address data. |

## Validation Rules

Exact address fields and validation constraints are **to be defined during implementation**.

| Field | Validation |
| --- | --- |
| **Authentication Session** | Must be valid and associated with an existing customer. |
| **Address Identity** | Must reference an existing address belonging to the authenticated customer. |
| **Updated Address Information** | Must satisfy the configured address validation rules. |

## Acceptance Criteria

- An authenticated customer can edit their saved address.
- An unauthenticated customer cannot edit an address.
- A customer can edit only their own address.
- An address belonging to another customer cannot be modified.
- Valid address changes are persisted successfully.
- Invalid address information is rejected.
- A failed update leaves the original address unchanged.
- The updated address is displayed after successful modification.
