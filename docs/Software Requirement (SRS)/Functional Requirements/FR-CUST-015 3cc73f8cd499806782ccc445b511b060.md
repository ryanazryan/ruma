## Overview

This requirement defines the process that allows an authenticated customer to confirm that an order has been received.

The confirmation provides an explicit customer action indicating that the delivery has been received and allows the order lifecycle to proceed according to the applicable order management rules.

## Description

The system shall allow an authenticated customer to confirm receipt of an eligible order belonging to their account.

The system shall verify the customer's authentication session and order ownership before processing the confirmation.

The system shall only allow order receipt confirmation when the order is in a state that permits customer confirmation.

The system shall update the order state according to the configured Order Management lifecycle after a successful confirmation.

## Actors

| Actor Role | Description |
| --- | --- |
| **Customer** | Confirms that an eligible order has been received. |
| **System** | Authenticates the customer, verifies order ownership and eligibility, processes the confirmation, and updates the order state. |
| **Order Management** | Maintains the order lifecycle and resulting order state. |

## Preconditions

- The customer has an existing account.
- The customer is authenticated.
- The authentication session is valid.
- The associated customer account exists.
- The selected order exists.
- The selected order belongs to the authenticated customer.
- The order is in a state that permits receipt confirmation.
- The system can access the order data.

## Trigger

The customer selects **Confirm Order Received** and confirms the action.

## Main Flow

1. The customer opens **Order History**.
2. The customer selects an eligible order.
3. The system displays the order details and available actions.
4. The customer selects **Confirm Order Received**.
5. The system displays a confirmation prompt.
6. The customer confirms the action.
7. The system verifies the customer's authentication session.
8. The system verifies that the order belongs to the authenticated customer.
9. The system verifies that the order is eligible for receipt confirmation.
10. The system processes the confirmation.
11. The system updates the order state according to the configured order lifecycle.
12. The system returns a successful response.
13. The updated order state is displayed to the customer.

## Alternative Flow

### A1 — Authentication Required

- The customer does not have a valid authentication session.
- The system rejects the request.
- The order is not modified.

### A2 — Order Not Found

- The selected order does not exist.
- The system rejects the request.
- The order is not modified.

### A3 — Order Does Not Belong to Customer

- The selected order belongs to another customer.
- The system rejects the request.
- The system does not expose the other customer's order information.

### A4 — Order Not Eligible for Confirmation

- The order is not in a state that permits receipt confirmation.
- The system rejects the request.
- The order remains in its current state.
- The system informs the customer that receipt confirmation is not currently available.

### A5 — Order Already Confirmed

- The order has already been confirmed as received.
- The system does not perform a duplicate state transition.
- The system displays the current order state.

### A6 — Order Confirmation Failure

- The system cannot persist the confirmation.
- The system returns an appropriate error response.
- The order remains unchanged.

## Postconditions

### If Successful

- The customer has confirmed receipt of the order.
- The order state is updated according to the configured lifecycle.
- The updated order state is visible to the customer.

### If Failed

- The order remains unchanged.
- No unrelated order information is modified.

## Business Rules

| Rule ID | Rule |
| --- | --- |
| **BR-CUST-075** | Only an authenticated customer can confirm receipt of an order. |
| **BR-CUST-076** | A customer can only confirm receipt for orders belonging to their own account. |
| **BR-CUST-077** | Order receipt confirmation is only allowed for eligible order states. |
| **BR-CUST-078** | A confirmed order must not be confirmed again as a new state transition. |
| **BR-CUST-079** | Order ownership and confirmation eligibility must be verified server-side. |
| **BR-CUST-080** | Receipt confirmation must update the order according to the configured order lifecycle. |

## Validation Rules

| Field | Validation |
| --- | --- |
| **Authentication Session** | Must be valid and associated with an existing customer. |
| **Order Identity** | Must reference an existing order. |
| **Order Ownership** | Must belong to the authenticated customer. |
| **Order Status** | Must permit receipt confirmation. |
| **Confirmation Action** | Must represent a valid customer confirmation. |

## Acceptance Criteria

- An authenticated customer can confirm receipt of an eligible order.
- An unauthenticated customer cannot confirm order receipt.
- A customer cannot confirm another customer's order.
- An order in an ineligible state cannot be confirmed.
- A successfully confirmed order transitions to the appropriate state.
- A previously confirmed order cannot undergo a duplicate confirmation transition.
- A failed confirmation does not modify the order.
