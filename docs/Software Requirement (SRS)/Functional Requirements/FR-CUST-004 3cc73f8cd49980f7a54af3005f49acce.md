## Overview

This requirement defines the process that allows an authenticated customer to view their saved shipping addresses.

The Address Book provides customers with access to addresses that can be managed and reused for customer purchasing and checkout activities.

## Description

The system shall allow an authenticated customer to view their saved shipping addresses.

The system shall retrieve the addresses associated with the authenticated customer's account and display them through the Customer Portal.

The system shall ensure that a customer can only view addresses belonging to their own account.

## Actors

| Actor Role | Description |
| --- | --- |
| **Customer** | Requests and views their saved shipping addresses. |
| **System** | Authenticates the customer, retrieves the customer's saved addresses, and returns the address information. |

## Preconditions

- The customer has an existing account.
- The customer is authenticated.
- The customer's authentication session is valid.
- The associated customer account exists.
- The system can access the database.

## Trigger

The customer opens the **Address Book** section of the Customer Portal.

## Main Flow

1. The customer opens the Customer Portal.
2. The customer selects **Address Book**.
3. The system verifies that the customer has a valid authentication session.
4. The system identifies the authenticated customer.
5. The system retrieves the saved shipping addresses associated with the customer account.
6. The system returns the saved addresses.
7. The system displays the saved addresses to the customer.
8. The customer can review the available saved addresses.

## Alternative Flow

### A1 — Authentication Required

- The customer does not have a valid authentication session.
- The system rejects the address request.
- The customer is redirected to the login flow.

### A2 — No Saved Addresses

- The authenticated customer does not have any saved addresses.
- The system returns an empty address collection.
- The system displays an appropriate empty state.
- The customer can proceed to the **Add Address** functionality.

### A3 — Customer Account Not Found

- The authenticated session references a customer account that is no longer available.
- The system rejects the request.
- No address information is returned.

### A4 — Address Retrieval Failure

- The system cannot retrieve the customer's saved addresses from the database.
- The system returns an appropriate error response.
- The address list is not displayed as successfully loaded.

## Postconditions

### If Successful

- The customer's saved shipping addresses are retrieved.
- The customer can view their own saved addresses.
- No address belonging to another customer is exposed.

### If No Addresses Exist

- An empty address collection is returned.
- The customer can access the Add Address functionality.

### If Failed

- No unrelated customer address information is exposed.
- No address data is modified.

## Business Rules

| Rule ID | Rule |
| --- | --- |
| **BR-CUST-016** | Only an authenticated customer can access their saved addresses. |
| **BR-CUST-017** | A customer can only view addresses associated with their own account. |
| **BR-CUST-018** | Address data must be retrieved using the authenticated customer's identity. |
| **BR-CUST-019** | The system must not expose saved addresses belonging to other customers. |
| **BR-CUST-020** | An empty address collection must be handled as a valid customer state when the customer has no saved addresses. |

## Validation Rules

| Field | Validation |
| --- | --- |
| **Authentication Session** | Must be valid and associated with an existing customer. |
| **Customer Identity** | Must correspond to the authenticated customer. |

No specific address-field validation is required when viewing saved addresses.

## Acceptance Criteria

- An authenticated customer can open the Address Book.
- An unauthenticated customer cannot access saved addresses.
- The system retrieves only addresses belonging to the authenticated customer.
- Saved addresses are displayed successfully when available.
- A customer with no saved addresses receives an appropriate empty state.
- A customer cannot access another customer's saved addresses.
- A failed address retrieval does not expose unrelated customer data.
- Viewing saved addresses does not modify address data.

## Notes

- Address Book is an MVP Customer capability.
- Address access must be restricted to the authenticated customer.
- The current Prisma schema does not yet contain an address data model.
- Exact address fields, persistence structure, ordering rules, and default-address representation must be finalized before implementation.
- The Address Book is intended to provide reusable shipping addresses for customer commerce activities.
- The exact relationship between saved addresses and the Checkout shipping-address flow must follow the final implementation of the Checkout module.
