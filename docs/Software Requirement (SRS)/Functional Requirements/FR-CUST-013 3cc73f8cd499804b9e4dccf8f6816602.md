## Overview

This requirement defines the process that allows an authenticated customer to track the current status and fulfillment progress of their order.

The tracking experience provides the customer with visibility into the order lifecycle after an order has been created.

## Description

The system shall allow an authenticated customer to view the fulfillment and status information of an order belonging to their account.

The system shall provide the current order status based on the order lifecycle managed by the Order module.

The system shall ensure that a customer can only track orders belonging to their own account.

Where shipment tracking information is available, the system shall display the relevant tracking information to the customer.

## Actors

| Actor Role | Description |
| --- | --- |
| **Customer** | Requests and views the fulfillment status of their order. |
| **System** | Authenticates the customer, verifies order ownership, retrieves order status, and returns available tracking information. |
| **Shipping Service** | Provides shipment tracking information when applicable and supported by the implemented shipping integration. |

## Preconditions

- The customer has an existing account.
- The customer is authenticated.
- The authentication session is valid.
- The associated customer account exists.
- The selected order exists.
- The selected order belongs to the authenticated customer.
- The order contains sufficient information to determine its current status.
- The system can access the required order data.

## Trigger

The customer selects **Track Order** from an order in Order History or Order Detail.

## Main Flow

1. The customer opens **Order History**.
2. The customer selects an order.
3. The customer selects **Track Order**.
4. The system verifies the customer's authentication session.
5. The system identifies the selected order.
6. The system verifies that the order belongs to the authenticated customer.
7. The system retrieves the current order status.
8. The system retrieves available shipment tracking information when applicable.
9. The system returns the available order tracking information.
10. The system displays the order status and fulfillment progress to the customer.

## Alternative Flow

### A1 — Authentication Required

- The customer does not have a valid authentication session.
- The system rejects the tracking request.
- The customer is redirected to the login flow.

### A2 — Order Not Found

- The selected order does not exist.
- The system rejects the tracking request.
- No order tracking information is displayed.

### A3 — Order Does Not Belong to Customer

- The selected order belongs to another customer.
- The system rejects the request.
- The system does not expose the other customer's order or tracking information.

### A4 — Tracking Information Not Available

- The order exists and belongs to the authenticated customer.
- Shipment tracking information is not yet available.
- The system displays the current order status without shipment tracking information.

### A5 — Shipping Tracking Service Unavailable

- The external shipping tracking service cannot provide tracking information.
- The system displays the latest available order status from the marketplace order data.
- The system informs the customer that detailed shipment tracking is temporarily unavailable.

### A6 — Order Retrieval Failure

- The system cannot retrieve the order or tracking information.
- The system returns an appropriate error response.
- No order information is incorrectly presented as current.

## Postconditions

### If Successful

- The customer's current order status is retrieved.
- Available shipment tracking information is displayed.
- The customer can understand the current progress of the order.

### If Tracking Information Is Unavailable

- The latest available order status remains visible.
- No incorrect tracking information is displayed.

### If Failed

- No unauthorized order or tracking information is exposed.
- The order is not modified.

## Business Rules

| Rule ID | Rule |
| --- | --- |
| **BR-CUST-062** | Only an authenticated customer can track their orders. |
| **BR-CUST-063** | A customer can only track orders belonging to their own account. |
| **BR-CUST-064** | Order ownership must be verified before tracking information is returned. |
| **BR-CUST-065** | The displayed order status must reflect the latest status available from the order system. |
| **BR-CUST-066** | Shipment tracking information must only be displayed when valid tracking data is available. |
| **BR-CUST-067** | Tracking a shipment must not modify the order. |

## Validation Rules

| Field | Validation |
| --- | --- |
| **Authentication Session** | Must be valid and associated with an existing customer. |
| **Order Identity** | Must reference an existing order. |
| **Order Ownership** | The order must belong to the authenticated customer. |
| **Tracking Information** | Must be valid when returned by the shipping service. |

## Acceptance Criteria

- An authenticated customer can track an order belonging to their account.
- An unauthenticated customer cannot access order tracking.
- A customer cannot track another customer's order.
- The current order status is displayed.
- Available shipment tracking information is displayed when present.
- The system can handle orders without available tracking information.
- Temporary shipping-service failures do not expose incorrect tracking information.
- Tracking an order does not modify the order.

## Notes

- Customer Order Tracking provides a customer-facing view of order fulfillment progress.
- The Order module remains responsible for the underlying order lifecycle.
- Shipment tracking integration depends on the shipping service implementation.
- Exact tracking fields, status mapping, and external tracking behavior are to be defined during implementation.
- The PRD defines Order Tracking as part of the Order Management capability set and expects customers to be able to track their orders.
