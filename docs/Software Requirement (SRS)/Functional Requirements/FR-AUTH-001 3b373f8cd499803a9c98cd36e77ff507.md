## Overview

Requirement ini mendefinisikan proses registrasi akun baru agar pengguna dapat membuat akun Moorlife Marketplace menggunakan alamat email yang valid. Setelah registrasi berhasil, pengguna akan menerima email verifikasi sebelum dapat menggunakan seluruh fitur aplikasi.

## Description

Sistem harus menyediakan mekanisme registrasi akun baru dengan mengumpulkan informasi dasar pengguna, melakukan validasi data, menyimpan akun secara aman, serta mengirimkan email verifikasi.

## Actors

| Actor | Role |
| --- | --- |
| Customer | Melakukan registrasi akun |
| System | Memvalidasi data, membuat akun, dan mengirim email verifikasi |

## Preconditions

- Pengguna belum memiliki akun dengan email tersebut.
- Pengguna mengakses halaman Register.
- Sistem dapat terhubung ke database.
- Layanan email aktif.

## Trigger

Pengguna menekan tombol **Register** setelah mengisi formulir registrasi.

## Main Flow

1. Pengguna membuka halaman Register.
2. Sistem menampilkan formulir registrasi.
3. Pengguna mengisi:
    - Nama Lengkap
    - Email
    - Password
    - Konfirmasi Password
4. Pengguna menekan tombol **Register.**
5. **Sistem melakukan validasi seluruh data.**
6. Sistem memastikan email belum digunakan.
7. Sistem mengenkripsi password menggunakan algoritma Argon2.
8. Sistem membuat akun baru dengan status **Unverified.**
9. Sistem membuat token verifikasi email.
10. Sistem mengirim email verifikasi.
11. Sistem menampilkan pesan bahwa registrasi berhasil dan pengguna diminta memverifikasi email.

## Alternative Flow

### A1 - Email sudah terdaftar

- Sistem menolak registrasi.
- Sistem menampilkan pesan: “Email sudah digunakan”

### A2 - Password dan konfirmasi password tidak sama.

- Registrasi dibatalkan.
- Sistem menampilkan pesan kesalahan.

### A3 - Format email tidak valid

- Registrasi dibatalkan.
- Sistem meminta pengguna memperbaiki email.

### A4 - Email gagal dikirim

- Akun tetap dibuat.
- Sistem memberi tahu pengguna bahwa email verifikasi gagal dikirim dan menyediakan opsi **Kirim Ulang Email Verifikasi.**

### Postconditions

Jika berhasil:

- Akun baru tersimpan.
- Password terenkripsi.
- Status akun Unverified.
- Token verifikasi dibuat.
- Email verifikasi dikirim.

Jika gagal:

- Tidak ada akun baru yang dibuat (kecuali pada skenario A4, ketika akun sudah berhasil dibuat tetapi pengiriman email gagal).

## Business Rules

| **Rule ID** | **Rule** |
| --- | --- |
| BR-AUTH-001 | Email harus unik. |
| BR-AUTH-002 | Password disimpan dalam bentuk hash menggunakan Argon2. |
| BR-AUTH-003 | Role default pengguna baru adalah Customer. |
| BR-AUTH-004 | Akun baru berstatus Unverified sampai email berhasil diverifikasi. |
| BR-AUTH-005 | Email verifikasi harus dikirim setelah registrasi berhasil. |

## Validation Rules

| Field | Validation |
| --- | --- |
| Full Name | Wajib diisi, panjang 3 - 100 karakter. |
| Email | Wajib diisi dan menggunakan format email yang valid. |
| Password | Wajib diisi, minimal 8 karakter. |
| Confirm Password | Harus sama dengan Password. |

**Catatan:** Persyaratan password seperti wajib mengandung huruf besar, angka, atau simbol dapat ditambahkan jika memang menjadi kebijakan keamanan proyek Anda. Untuk MVP, minimal 8 karakter sudah cukup.

## Acceptance Criteria

- Pengguna dapat membuat akun baru dengan data yang valid.
- Email yang sudah terdaftar tidak dapat digunakan kembali.
- Password tidak disimpan dalam bentuk plain text.
- Email verifikasi berhasil dibuat dan dikirim.
- Akun baru memiliki status **Unverified.**
- Sistem menampilkan pesan registrasi berhasil.
