## Overview

This requirement defines the process that allows an authenticated customer to update their editable profile information.

The customer can access an edit interface from the Customer Profile area and submit updated profile information.

## Description

The system shall allow an authenticated customer to update their editable profile information.

The system shall validate submitted profile information before persisting the changes.

The system shall associate the update with the currently authenticated customer.

The system shall not allow a customer to modify another customer's profile information.

## Actors

| Actor Role | Description |
| --- | --- |
| **Customer** | Provides and submits updated profile information. |
| **System** | Authenticates the request, validates the submitted information, updates the customer's profile, and returns the updated result. |

## Preconditions

- The customer has an existing account.
- The customer is authenticated.
- The authentication session is valid.
- The associated user account exists.
- The system can access the database.
- The customer has permission to update their own profile.

## Trigger

The customer selects **Edit Profile** and submits updated profile information.

## Main Flow

1. The customer opens the **Profile** section.
2. The system displays the customer's current profile information.
3. The customer selects **Edit Profile**.
4. The system displays the editable profile fields.
5. The customer modifies the allowed profile information.
6. The customer submits the profile changes.
7. The system verifies the customer's authentication session.
8. The system validates the submitted information.
9. The system identifies the authenticated customer.
10. The system updates the customer's profile information.
11. The system returns a successful response.
12. The updated profile information is displayed to the customer.

## Alternative Flow

### A1 — Authentication Required

- The customer does not have a valid authentication session.
- The system rejects the update request.
- No profile information is modified.

### A2 — Invalid Profile Data

- The submitted profile information does not satisfy the required validation rules.
- The system rejects the update request.
- Existing profile information remains unchanged.

### A3 — Customer Account Not Found

- The authenticated session references a customer account that is no longer available.
- The system rejects the update request.
- No profile information is modified.

### A4 — Profile Update Failure

- The system cannot persist the updated profile information.
- The system returns an appropriate error response.
- Existing profile information remains unchanged.

## Postconditions

### If Successful

- The customer's editable profile information is updated.
- The updated information is persisted.
- The customer can view the updated profile information.

### If Failed

- Existing profile information remains unchanged.
- No unrelated customer data is modified.

## Business Rules

| Rule ID | Rule |
| --- | --- |
| **BR-CUST-005** | Only an authenticated customer can update their profile. |
| **BR-CUST-006** | A customer can only update their own profile. |
| **BR-CUST-007** | Submitted profile information must satisfy the configured validation rules. |
| **BR-CUST-008** | Profile updates must not modify unrelated account or security information. |
| **BR-CUST-009** | The system must persist profile changes only after successful validation. |

## Validation Rules

Untuk saat ini saya sengaja **tidak menetapkan field validation yang belum didefinisikan oleh PRD/SRS**.

| Field | Validation |
| --- | --- |
| **Authentication Session** | Must be valid and associated with an existing customer. |
| **Editable Profile Information** | Required validation rules shall follow the final Customer Profile data model. |

> `Full Name` adalah kandidat field editable karena saat ini memang ada di model `User`, tetapi aturan baru seperti minimum/maximum karakter sebaiknya mengikuti validation backend yang kita tetapkan saat implementasi.
> 

## Acceptance Criteria

- An authenticated customer can open Edit Profile.
- An unauthenticated customer cannot update profile information.
- A customer can update their own editable profile information.
- A customer cannot update another customer's profile.
- Invalid profile information is rejected.
- A successful profile update is persisted.
- The updated profile information can be viewed after the update.
- A failed update does not overwrite the existing profile information.

## Notes

- The current `User` model contains `fullName` and `email`.
- The final list of editable profile attributes should follow the approved Customer data model.
- Email should not be treated as an editable profile field unless a separate email-change requirement is formally defined.
- Password changes remain part of **AUTH-007 — Change Password**, not Customer Profile.
