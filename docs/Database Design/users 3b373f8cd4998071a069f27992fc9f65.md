# users

# Overview

Tabel **users** menyimpan informasi identitas dan akun seluruh pengguna Moorlife Marketplace. Tabel ini menjadi pusat autentikasi dan otorisasi sistem, serta digunakan oleh seluruh modul yang membutuhkan informasi pengguna, seperti Customer, Distributor, Warehouse, Finance, Owner, dan Administrator.

Setiap pengguna memiliki identitas unik berupa UUID dan alamat email yang bersifat unik. Data pada tabel ini menjadi referensi utama bagi tabel-tabel lain yang berhubungan dengan pengguna.

# Column Specifications

| Column | Data Type | Nullable | Default Value | Constraints | Description |
| --- | --- | --- | --- | --- | --- |
| id | UUID | No | Generated UUID | Primary Key | Unique identifier untuk setiap pengguna. |
| full_name | VARCHAR(100) | No | - | - | Nama lengkap pengguna. |
| email | VARCHAR(255) | No | - | Unique | Alamat email pengguna yang digunakan untuk autentikasi. |
| password_hash | TEXT | No | - | - | Password yang telah dienkripsi menggunakan Argon2. |
| role | user_role | No | CUSTOMER | Enum | Peran pengguna dalam sistem. |
| account_status | account_status | No | PENDING_VERIFICATION | Enum | Status akun pengguna. |
| email_verified_at | TIMESTAMPTZ | Yes | NULL | - | Waktu ketika email berhasil diverifikasi. |
| last_login_at | TIMESTAMPTZ | Yes | NULL | - | Waktu terakhir pengguna berhasil login. |
| created_at | TIMESTAMPTZ | No | CURRENT_TIMESTAMP | - | Waktu data dibuat. |
| updated_at | TIMESTAMPTZ | No | CURRENT_TIMESTAMP | - | Waktu terakhir data diperbarui. |
| deleted_at | TIMESTAMPTZ | Yes | NULL | Soft Delete | Menandai data telah dihapus tanpa menghapus secara permanen. |

# Indexes

| Index Name | Type | Columns | Purpose |
| --- | --- | --- | --- |
| users_pkey | Primary Key | id | Identitas utama setiap pengguna. |
| users_email_key | Unique | email | Mencegah email duplikat dan mempercepat proses login. |
| idx_users_role | Index | role | Mempercepat pencarian berdasarkan peran pengguna. |
| idx_users_account_status | Index | account_status | Mempercepat filter berdasarkan status akun. |
| idx_users_deleted_at | Index | deleted_at | Mengoptimalkan query pada data aktif (soft delete). |

# Constraints

| Constraint | Description |
| --- | --- |
| Primary Key | `id` harus unik untuk setiap pengguna. |
| Unique Constraint | `email` harus unik dan tidak boleh digunakan lebih dari satu akun. |
| NOT NULL | `full_name`, `email`, `password_hash`, `role`, `account_status`, `created_at`, dan `updated_at` wajib memiliki nilai. |
| Enum Constraint | Nilai `role` dan `account_status` hanya boleh berasal dari Enum yang telah ditentukan. |
| Soft Delete | Penghapusan data dilakukan menggunakan `deleted_at` tanpa menghapus record secara permanen. |

# Relationships

| Related Table | Relationship | Description |
| --- | --- | --- |
| verification_tokens | One-to-Many | Satu pengguna dapat memiliki banyak token verifikasi. |

# Business Rules

| Rule ID | Business Rule |
| --- | --- |
| BR-USER-001 | Email harus unik pada seluruh sistem. |
| BR-USER-002 | Password wajib disimpan dalam bentuk hash menggunakan Argon2. |
| BR-USER-003 | Role default pengguna baru adalah CUSTOMER. |
| BR-USER-004 | Status awal akun adalah PENDING_VERIFICATION. |
| BR-USER-005 | Akun hanya dapat berubah menjadi ACTIVE setelah email berhasil diverifikasi. |
| BR-USER-006 | Penghapusan akun menggunakan mekanisme Soft Delete. |

# Security Considerations

- Password tidak boleh disimpan dalam bentuk plaintext.
- Password wajib menggunakan algoritma hashing Argon2.
- Email diperlakukan sebagai informasi unik pada sistem.
- UUID digunakan sebagai Primary Key untuk mengurangi risiko enumerasi data.
- Seluruh operasi autentikasi harus menggunakan koneksi HTTPS.
- Data pengguna yang telah dihapus tetap disimpan menggunakan mekanisme Soft Delete untuk kebutuhan audit dan pemulihan data.
